# 前端 → 合约（直接链上交互）

> 用途：被问「前端哪些操作不经过后端、直接碰合约」时回答。前端 = `perpetual-contract/others/fe/`（Next.js + wagmi/viem/rainbowkit）。

## 0. 核心原则

**前端碰合约分两类**：

1. **纯本地签名（不广播）**：EIP-712 `signTypedData` 签名订单——这只是生成签名，**不产生交易**，签名结果交给后端撮合。
2. **真实链上交易（广播）**：入金/出金/建子账户等**资产管理**操作，直接发交易，不经过后端。

大部分「交易行为」走后端撮合 + 后端上链；只有「资金管理」前端直接上链。

## 1. 前端直接碰合约的操作

| 前端操作 | 合约方法 | 是否广播 | 说明 |
|---|---|---|---|
| 连接钱包 | （wagmi/rainbowkit） | — | 只读账户，不调合约 |
| **签名订单** | EIP-712 `signTypedData` | ❌ 不广播 | 本地生成签名，交给后端 |
| 授权 USDC | `USDC.approve(dealer, amount)` | ✅ | 入金前先授权 |
| **入金（链上轨道）** | `Dealer.deposit(primaryAmount, secondaryAmount, to)` | ✅ | 资金进链上 primaryCredit |
| **出金（两步）** | `Dealer.requestWithdraw` → `executeWithdraw` | ✅ | 时间锁后取款 |
| 快速出金 | `Dealer.fastWithdraw(...)` | ✅ | 白名单跳过时间锁 |
| 建子账户 | `SubaccountFactory.newSubaccount()` | ✅ | 隔离风险 |
| 子账户执行 | `Subaccount.execute(to, data, value)` | ✅ | 以子账户身份交易/存款 |

## 2. 签名订单（最关键，但它不上链）

用户下单时，前端用 `viem.signTypedData` 签 EIP-712 订单，domain 和类型如下：

```
Domain:
  name: "MetaNode"
  version: "1"
  chainId: <链ID>
  verifyingContract: <Dealer 地址>

类型:
  Order(address perp,address signer,int128 paperAmount,int128 creditAmount,bytes32 info)
```

- `info`（bytes32）由 `makerFeeRate<<192 | takerFeeRate<<128 | expiration<<64 | nonce` 打包（eip712.go:36-50）。
- 签出来的 `(r,s,v)` 和订单一起 POST 给后端 `/orders`。
- **签名这一步不上链、不花 gas**——这就是「链下撮合」的关键：用户授权了订单，但成交前不需要付 gas。

> 注意 `verifyingContract` 必须是 Dealer 地址，且和链上 `domainSeparator`（`MetaNodeStorage.sol:38` 用 `address(this)` 构建）一致，否则链上验签失败。

## 3. 入金：两条轨道

用户入金有两条轨道（面试必讲）：

| 轨道 | 操作 | 结果 | 谁记 |
|---|---|---|---|
| **Treasury 轨道** | `USDC.transfer(usdcTreasury)` | 链下 ledger_balances 记一笔 | 后端 TreasuryDepositWatcher 监听 |
| **Dealer 轨道** | `USDC.approve(dealer)` + `Dealer.deposit` | 链上 primaryCredit 记一笔 | 链上合约 |

- Treasury 轨道是「转给国库地址」，后端扫描 `Transfer` 事件记到 `deposits`/`ledger_balances`（链下账本）。
- Dealer 轨道是「存进 Dealer 合约」，链上 `primaryCredit` 直接是保证金。
- 两套并存，`/balance` 接口会把两者相加（getbalancelogic.go:35 + :48）。

## 4. 出金：两步（时间锁）

```
Dealer.requestWithdraw(from, primaryAmount, secondaryAmount)   // 登记，记 block.timestamp + withdrawTimeLock
        ↓ 等时间锁到期
Dealer.executeWithdraw(from, to, isInternal, param)            // 真正转出
```

- `withdrawTimeLock` 由 owner 通过 `setWithdrawTimeLock` 设置。
- `fastWithdraw` 是白名单/未禁用时跳过时间锁的一步取款。

## 5. 子账户（Subaccount）

- `SubaccountFactory.newSubaccount()` 用 EIP-1167 Clone 创建一个子账户合约，owner 是用户钱包。
- 子账户可以持有自己的仓位/余额，用于**隔离风险**（不同策略/资金分开）。
- 用户通过 `Subaccount.execute` 以子账户身份调用 Dealer 的交易/存款方法。

## 6. 前端技术栈对应（面试一句话）

前端用 **wagmi/viem** 做钱包连接和合约调用，**rainbowkit** 做连接按钮，**@tanstack/react-query** 管服务端状态，**@supabase/supabase-js** 订阅行情实时推送，**lightweight-charts** 画 K 线。

## 7. 面试点小结

1. **签名 ≠ 交易**：EIP-712 `signTypedData` 只生成签名不上链，这是「用户授权但不用付 gas」的核心。
2. **只有资金管理前端直接上链**，交易行为走「签名→后端撮合→后端上链」。
3. **两条入金轨道**：Treasury（链下记账）vs Dealer（链上保证金）。
4. **出金有时间锁**：`requestWithdraw` + `executeWithdraw` 两步，防「出金后马上爆仓」的跑路风险。

# 前端 → 后端（HTTP API 完整映射）

> 用途：被问「前端怎么跟后端交互」「这些接口是干嘛的」时的速查。基准目录：`perpetual-contract/others/backend/`（go-zero REST，所有接口前缀 `/api/v1`）。

## 0. 一个关键事实：路由真相源不是 metanode.api

- `metanode.api` 只定义 17 个端点（分 7 组），**不含 auth**。
- 实际运行时 `internal/handler/routes.go` 注册了 **22 条**，且它头部虽写「Code generated by goctl. DO NOT EDIT.」，**实际被人手改过**：额外加了 5 个 `.api` 里没有的端点——`auth/nonce`、`auth/verify`、`funding-rate/latest`、`open-quote`、`order-preview`。
- 面试若被问「路由唯一来源」，正确说法：`.api` 是生成模板的源，但运行时 `routes.go`（已被手工编辑）才是真正生效的。

## 3. 鉴权流程（/auth/nonce + /auth/verify）

**整体：EIP-191 personal_sign → 一次性 nonce → 签发 JWT，但 JWT 后续从未校验。**

1. `POST /auth/nonce`（noncelogic.go:42-75）：校验 JwtSecret → 校验地址 → 生成 16 字节随机 nonce → 拼明文 `Sign in to MetaNode.\n\nWallet: <addr>\nNonce: <nonce>` → 写 Redis（`SETEX metanode:wallet_auth_nonce:<addr> <nonce> <ttl=15min>`）→ 返回 `{nonce, messageToSign}`。
2. `POST /auth/verify`（verifylogic.go:66-133）：从 Redis 取 nonce（一次性删）→ 比对消息 → `verifyPersonalSign`（`accounts.TextHash` = EIP-191 `"\x19Ethereum Signed Message:\n<len><msg>"`，`crypto.SigToPub` 恢复公钥比对地址）→ 可选 upsert `users` 表 → 签 HS256 JWT（`sub=addrLower, iat, exp=168h`）。

**面试必讲**：全仓库没有 `rest.WithJwt`、没有 `Authorization` 解析、没有 `jwt.Parse`。**JWT 只签发、不校验**，业务接口身份来自请求体里的 `signer`/`trader` 地址（自报身份）。这是安全缺口。

## 4. POST /orders 完整链路（最重要的一条）

前端传 `{perp, signer, paperAmount, creditAmount, makerFeeRate, takerFeeRate, expiration, nonce, signature}`：

1. **校验**（createorderlogic.go:37-48）：expiration 未过期、地址合法、paper/credit 异号（一正一负代表多空）。
2. **构造订单**（:50-65）：`model.Order{...}`，Status=0(Pending)。
3. **算 EIP-712 digest 当 orderId**（:67-76）：`chain.OrderDigestWith` → `SignableOrderHash`（eip712.go:72-78）= `keccak256(0x19‖0x01‖domainSeparator‖structHash)`。**这个 digest 的 hex 就是 orderId**——「订单哈希 = 订单 ID」，与合约里 `orderFilledPaperAmount[hash]` 对齐，天然去重。
4. **验签**（:78-82，**仅当 `svcCtx.Chain != nil`**）：`VerifyEOASignature` 重算 digest → `SigToPub` 恢复地址比对 signer。只支持 EOA，不支持 EIP-1271 合约钱包。
5. **查重 + 入库**（:84-92）：`FindOne(orderId)` 已存在则 400；否则 INSERT `orders` 表。
6. **进撮合**（:94-100）：`MatchEngine.AddOrder(order)`；入队失败则回滚 DB 状态为 Cancelled。
7. 返回 `{orderId}`。

## 6. 面试点小结

1. **JWT 不校验**（见上）。
2. **下单验签可跳过**：`if svcCtx.Chain != nil` 才验，链客户端没配时下单不验签（教学项目常见）。
3. **两个空实现**：`/withdraws` 和 `/liquidations` 都是 `// todo` 直接 return。
4. **orderId = EIP-712 digest**：既是验签目标又是主键。
5. **/balance 容错**：链上 `GetCreditOf` 失败不 500，只返回链下 ledger 部分（getbalancelogic.go:49-52）。
